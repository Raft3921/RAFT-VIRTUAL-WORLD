# Stable camera, anatomical acrobatic hits and lower buffering — bodyhit131

Parkour camera rotation and wall banking are removed, including the camera-motion module. Full body flips, automatic mantle and hidden contextual UI remain. Normal aiming, weapon recoil and small existing airborne/landing presentation remain.

Acrobatic hit detection no longer uses three enlarged enclosing boxes. The new pure shared parkour-rig module defines deterministic limb joint angles and anatomical oriented boxes. Avatar rendering consumes the same joints and body quaternion; incidental locomotion offsets and lingering stance blends are removed during the acrobatic pose so they cannot diverge from server anatomy. Head aim uses the same clamped local angles, with wall-running head counter-rotation. The skin-7 dimensions/pivots are derived from the existing gyoza JEM; slim dimensions follow the existing avatar geometry, including overlay inflation, split arm/leg segments and joint caps. Clothing is included; cosmetic weapons and crowns are excluded.

Full three-axis slab intersections test the individual rotated head, torso, upper/lower arms and upper/lower legs rather than the empty space inside a broad envelope. Bullet sweeps evaluate mid-slice orientation in at most 5 ms slices, with relative root motion and no inflated endpoint union or cross-action part-index matching. Knife sweeps and blast distance use the same body boxes. Knife requests carry the same bounded, server-validated render timestamps as gunshots for rewind to the displayed target posture. Authoritative hit-history/rewind remains; no client-provided geometry is trusted. Non-acrobatic posture behavior remains the existing implementation. Movement's wall/ground collider is distinct from these combat hitboxes and is not claimed to be a per-mesh collision solver.

Input state publication targets 60 Hz instead of 30 Hz, with matching 12 ms minimum acceptance on Worker and LAN so alternate 60 Hz packets are not discarded by the old 25 ms gate. Gun flight ticks target 60 Hz instead of 50 Hz. Combat rendering uses a bounded adaptive interpolation budget based on 0.9 snapshot intervals plus measured arrival jitter, clamped to 16–55 ms instead of the previous 45–75 ms nominal range. It retains interpolation and authoritative render-time rewind instead of extrapolating opponents through cover. Local input prediction and immediate predicted firing feedback remain. Physical network/transport/render latency cannot be zero.

No tests, syntax checks, browser sessions, device/multiplayer/visual checks or latency benchmarks were performed, following the user instruction. The geometry alignment and latency improvements are implemented but unverified at runtime. Deployment metadata establishes publication only.
