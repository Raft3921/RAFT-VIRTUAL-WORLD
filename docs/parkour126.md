# First-person body and shared wall actions — parkour126

First-person rendering retains the selected avatar torso and legs. The local head is masked for the main camera, retaining its shadow, and duplicate arms are hidden when the weapon viewmodel is active. Masks are restored after the main pass for other views. Climbing and acrobatic actions expose the avatar arms instead of the weapon rig. Scoped aiming retains its clear scope view.

Combat movement derives wall contacts and action budgets from shared world solids on both the authoritative server and client prediction. Dash-jumping along a wall runs along it for at most 1.2 seconds. Another jump near a wall kicks away with an upward impulse; repeated kicks require a different wall and are limited to three before landing. A frontal dash jump climbs for at most 0.9 seconds, automatically handing off to the existing clearance-checked lift-and-pull mantle when a reachable ledge is available. Backward input plus a grounded jump initiates a backflip when standing clearance permits. Landing resets airborne action budgets. Existing slide, immediate ground stop and entry teleport barriers remain.

Avatar poses animate reaching shoulders/elbows, climbing legs, wall-running stride and a tucked backflip. The camera stays level. Action state, progress and wall side flow through server snapshots, prediction acknowledgements, remote interpolation, hit history and replay posture. Bullet boxes follow the acrobatic body conservatively. Shooting, aiming, slashing and starting a reload are blocked while hands are occupied by climbing, mantling, a backflip or a wall kick. Wall running allows firing.

Contextual muted action hints, progress and a control guide in the combat menu explain the actions. Existing jump inputs work on keyboard, touch and controller. Wall contact dust uses bounded existing effect pools. No tests, syntax checks, browser sessions, visual previews or multiplayer/device verification were performed, following the user instruction. Publishing and release metadata do not establish gameplay acceptance.
